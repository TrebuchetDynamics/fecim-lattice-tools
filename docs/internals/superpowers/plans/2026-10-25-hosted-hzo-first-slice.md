## Brief and decisions

Build the first usable React module for researchers/students already using the Fyne Hysteresis workspace: change material/model/drive, observe real model history, program levels, inspect diagnostics and read every scientific result without interpreting a picture. The reference is the existing workflow, not Fyne widget geometry. This is a module replacement project, not a fixed HZO screenshot/demo or an all-module dashboard rewrite.

- User choices: React primary, Fyne deprecated, Hysteresis first; derive behavior from the existing application rather than interview the owner about its controls.
- Planner call: retain the existing material catalogue and literature-superlattice default selection; open in Sine mode, paused, with explicit Run/Pause/Reset rather than Fyne's automatically running write/read demo. Other physical defaults remain Go-owned. Programming remains a supported mode, not removed to simplify the opening screen.
- Planner call: one React/TypeScript/Vite app in `web/`, replacing Astro's home while preserving useful content/citations/links. Home and `/hysteresis` are shared routes in hosted/local builds; no second site, placeholder dashboard, desktop wrapper or TS physics.
- Planner call: reuse the Go solvers/controllers and extract UI-independent orchestration into `workbench/hysteresis`; do not wrap `gui.App` in WASM or mistake the existing headless viewmodel for complete GUI parity. Its `Start`/`Stop` are empty and it lacks model/drive/programming controls.
- Planner call: use the browser Go Worker for the same admitted Hysteresis capabilities in both profiles. The local same-origin server adds explicitly requested root-confined file operations; it is not a hosted fallback or a remote computation service. Larger unsupported jobs show a truthful capability limit, not altered physics.
- No new scientific model, parameter fitting, hardware/device-validation claim, experimental-validation promotion, public release/DOI claim, other module screen or global launch-default change. Fyne deletion is a separately authorized change after module qualification; retain existing compatibility entry points/tests in this batch.

## Go seams and invariant contract

The new package is an orchestration adapter over existing Go core, not another physics model. Preserve original solver/controller equations, presets, sign/guard behavior and scientific regression tolerances. Native characterization tests against the existing GUI's deterministic `UpdatePhysics(dt)` seam establish behavior before extracting it; UI-free packages must not import Fyne, native persistence, external tools or file logging. Existing `module1-hysteresis/pkg/simulation.Engine` alone is insufficient: it only wraps Preisach and has different waveform/default timing.

Selected public seams (producer task may choose reversible private names, but must keep these public handoffs consistent):

- HYS-CORE: `hysteresis.NewSession(Config) (*Session,error)`; `Session.Apply(Command) (Snapshot,error)`; `Session.Advance(Budget) (Snapshot,error)`; `Session.Page(PageQuery) (Page,error)`. Commands/config carry explicit SI values, material/model IDs, mode and seed; snapshots carry revision, model/assumptions, availability, canonical quantities and Go display/speech. Page queries bind revision and return 32 rows plus position/count; stale revisions return an explicit stale-state error.
- HYS-PROGRAM: `NewProgrammer(*Session, ProgramConfig)` with `Apply`, bounded `Advance` and `Snapshot`; uses the shared session drive/solver rather than its own numerical engine. Owns ISPP/manual target/calibration state and returns the same core snapshot vocabulary plus typed programming/calibration data. Time-resolved mode reports `legacy_protocol_unavailable` with a Go explanation and no fabricated samples; restoring it is outside this migration. Changing settings invalidates prior calibration/export eligibility; no global RNG or implicit time-based seeds.
- HYS-ANALYSIS: `NewAnalysis(AnalysisRequest) (*AnalysisJob,error)` and bounded `Advance`/`Page`/`Result`; request copies selected Go context/input revision and explicit parameters, but result separately identifies the actual PUND/FORC diagnostic profile/model and applied parameters, not the loop engine. Reference data retains evidence status. An analysis never mutates the live loop session. Caller-provided reference bytes are read-only/unverified; no arbitrary path input in the browser API.
- HYS-WORKER alone owns the production operation registry and typed JSON envelope: protocol/build/model versions, session/request/revision IDs, operation, input; replies result/progress/error with the same IDs. Dispatches to the three producer APIs. One active computation per Worker, cooperative bounded work/yield, explicit terminal status and hard terminate/recreate recovery. No UI-owned scientific defaults/conversion/rounding, no target-specific normalization for parity.
- HYS-UI alone owns React route/component registration. It consumes the Worker envelope and renders all completed producer features, not fake future tabs. HYS-LOCAL owns the additive same-origin file API and build embedding, not a competing compute UI.

Canonical SI remains separate from presentation. Extend existing `workbench/presentation.Value`/`FormatMetric` vocabulary (currently unsupported field units must not silently become “Not available”). Convert E to MV/cm using 1e-8 and P to µC/cm² using 100 in Go only; preserve unavailable reasons, negative/zero/exponent speech and row/branch context. Do not change canonical values to match display rounding.

### Diagnostic protocol decision (builder finding resolved)

The behavioral oracle is the existing **GUI** diagnostic, not the different headless viewmodel implementation. PUND preserves `pund_panel.go:runPUND`: fixed illustrative HZO-demo parameters Ec=3e7 V/m, Ps=0.25 C/m², `TanhEverett` Delta=0.3×Ec, drive=5×Ec, width=100e-9 s, dt=5e-9 s, area=1e-12 m². This is a versioned `legacy-pund-demo` simulation profile, **not** the selected loop preset and not a claim that these are `DefaultHZO`'s parameters. It runs only on explicit action, without the GUI constructor's auto-run.

FORC preserves `forc_panel.go:runFORCWorkflow`/`guiFORCEverett`: selected material Ps, user Emax, and the existing weighted Everett expression `ps*x*exp(-(center²)/(2*0.2²))` with its original clamps; share/extract that Go function rather than rewrite it in JS. Keep GUI defaults Emax=1.0 **V/m**, reversals=21, grid resolution=21, and positive/minimum-three validation. Do not reinterpret 1 V/m as 1 MV/cm or silently substitute the headless `TanhEverett` stack. The simplified GUI profile is a separate Preisach diagnostic, not a physical L-K FORC experiment. Future scientific protocol improvements require separate authorization, not a parity workaround.

Both diagnostics remain usable when the loop selects L-K, but UI/results/export must state their independent Preisach protocol and exact applied parameters. Selected-loop model/temperature/stress are context only and are not falsely reported as used by these diagnostics. Characterization tests compare GUI numerical constructions and shared underlying routines; headless diagnostic tests remain compatibility guards for their own distinct profiles.

Initial safety bounds are planner decisions, not performance evidence: one active Worker session/job, 32 visible table rows/page, at most 100000 retained samples, 2000 supplementary plot points, 256 outer steps/advance call, and 1 MiB request/reference-byte envelope. Enforce before allocation, reject NaN/Inf/overflow/malformed/unsupported settings without altering current valid state; bounded inner solver work and cancellation checks remain mandatory. FORC permits 3–64 reversal curves, at most 256 samples/curve, and grid resolution 3–256 on each axis; admit smaller measured settings if needed, label limits explicitly, never silently truncate a result or change physical accuracy. Go owns actual per-operation supported caps after measurement; raw work caps are not responsiveness claims.

For performance qualification adopt the prior candidate guardrails as delegated engineering targets: WASM/runtime/Worker <=6 MiB raw, <=1.5 MiB Brotli (<=2 MiB gzip); complete first Hysteresis route <=2 MiB Brotli transfer; explicit cold Sine-loop result <=5 s under 10 Mbit/s +100 ms RTT. Measure the actual production module and reference preset/inputs, not the old eight-point example. Record runtime/hardware, cold cache reset, transferred byte filter, result-complete marker and repeated measurements. Shape only a worker-owned private static test server/proxy (aggregate 10 Mbit/s transfer, added 100 ms request round-trip delay); never alter host-wide networking or user traffic. WORKER measures module/driver bounds provisionally; UI additionally gates the real complete React route. Additional modes need their own admission/cancellation measurements; do not apply the example-only 250 ms budget to them. A miss is a recorded failing gate requiring bounded repair/replanning, not permission to remove modes, weaken parity, retune physics or claim fast behavior.

State is ready/loading/running/paused/completed/cancelled/failed, with previous results explicitly labelled stale if settings change. Table cells expose Go speech through normal Orca table reading. No virtualization; every retained sample is reachable. Plot has no per-point Tab stops and no unique information absent from tables/text. At narrow widths/zoom, use normal document flow, not clipped three-pane Fyne geometry.
