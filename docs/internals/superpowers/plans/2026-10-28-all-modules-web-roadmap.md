## Outcome and definition of done

Researchers/students can use every currently implemented module workflow from one React/TypeScript/Vite application, without a Fyne-only scientific feature path. Go remains the authority for models, defaults, validation, numerical results, units/speech, evidence, identities, sorting/paging and exports. Preserve CLI and existing scientific regression behavior. Port useful workflows and accessible equivalents, not Fyne widget geometry, accidental UI timing, no-op buttons or misleading claims.

The complete roadmap covers: Hysteresis; Crossbar; MNIST; Circuits; Comparison; EDA; Documentation; shared projects/configuration/experiments/results; dual-profile builds; provenance/security/accessibility; and qualified legacy retirement. A module is not qualified merely because its descriptor says `functional`, a route exists or a mocked screenshot looks correct. Required proof is real core execution, complete declared workflow coverage, honest unavailable states, profile isolation, numerical or artifact equivalence, browser interaction tests and actual applicable manual qualification. Final default switch/deletion is a later implementation outcome, never a planning edit.

Non-goals: new physics, TS numerical models, a second marketing app, hosted computation service, localhost probing, accounts/cloud storage, WebGPU rewrite, automatic package/PDK/container downloads, new training features absent from the existing GUI, invented hardware accuracy/speed/energy claims, publication/DOI/JOSS/outreach or rewriting every existing CLI utility into a browser page. ## Shared architecture and contracts — WEB-WORKBENCH

Reuse the actual HYS app, Go server, auth/session/bootstrap and manifest checks. Extend, do not create a second listener or another root-trust model. The accepted `/api/v1` project/experiment/run/report/export routes and ETag/status semantics in the browser design remain normative. Native operations call `project.ReadConfiguration/NewConfigurationEditor`, `study.ValidateProjectRoot/RunRoot/GenerateReportRoot/ExportRunRoot`, `experiment.LoadRunsRoot/Analyze` and existing serializers directly, not CLI prose/subprocesses. Project mutations serialize; slow SSE readers cannot block computation; cancel acknowledgement is not terminal cancellation; closing/restarting a browser does not delete runs or silently cancel server jobs. Reads do not regenerate reports or write history.

Build real four-view functionality: discover/open/create/close only beneath launch-granted roots; field-only comment-preserving configuration edits with exact If-Match, 428/412 conflicts and textual yours/on-disk values; start/cancel/reconnect/recover jobs with Go counters; inspect/filter/sort/page stable run identities, compare 2–4 runs, evidence and plots; explicitly verify/report/export selected eligible runs without recomputation. Reuse BWC native prerequisites rather than duplicate their implementations. Small hosted studies use bounded in-memory Go bundles and the same Expand/ID/Evaluate/Analyze/report path; no disk wrapper or scientific downloads. The checked-in eight-point study's original results.json remains the independent byte-parity gate.

### Protocol and registration ownership

- Add storage-independent Go DTOs/interfaces in `workbench/moduleapi/`: `ModuleDescriptor` (ID, implemented features, profile capabilities, reasons, schema/model version), `Command` (action ID, input strings/intent tokens, input revision and opaque resource references), `Snapshot` (revision, Go fields/actions/status/evidence, table pages, plots), and a bounded job/session port. Each numeric cell retains canonical value/unit plus Go display/speakable/availability/reason. Do not parse legacy formatted `Metric.Value` back into fake scientific values.
- `ModulePort` in `shared/viewmodel/types.go` is a compatibility contract, not completeness evidence. Each module adds a web port over its real core. New web capabilities are unavailable until the module implements the new port; preserve existing compatibility actions/tests except task-owned truthful bug repairs. Do not expose `KnownDescriptors().StatusFunctional` as a web-readiness or verification claim.
- WEB-WORKBENCH alone installs the native factory/dispatch registry for known module IDs and generic routes: `/api/v1/modules/{id}/sessions`, session actions/snapshots, and jobs with explicit progress/cancel. Factories use existing memory-only viewmodel constructors and a web-port capability check; native root/file capabilities stay outside browser DTOs. No constructor may read arbitrary cwd/home paths, auto-save or invoke tools. Modules own their actual port implementation and bind validated bytes/opaque granted references through the interface; no repeated central registry edits.
- UI route ownership is also installed once by WEB-WORKBENCH: home, `/docs`, `/hysteresis` compatibility route, four research views and `/modules/{id}`. Discover module screen files by a fixed Vite build-time glob, `web/src/modules/*/Screen.tsx`; lazy load only actually built screens whose Go capability exists. Each module owns one Screen entry and its component subtree, not a shared route registry. Hysteresis gets an adapter to its existing screen rather than a rewritten implementation. Missing screens/capabilities explain unavailability without posing as completed modules.
- Hosted numerical feature entries are independently lazy-loaded Go/WASM bundles: existing Hysteresis plus crossbar, circuits and comparison. Docs search is a separate read-only Go content/index operation. Do not eagerly link EDA/MNIST/filesystem/GPU/tool code into a universal hosted binary. One active scientific Worker computation per tab; preserve explicit queued/busy/cancel semantics, previous-result revisions and route-navigation focus. Reading docs must not implicitly reset/cancel an experiment.
- The native and Worker transports use the same Go command/snapshot/terminal vocabulary; native jobs may hold root capabilities, Worker jobs cannot. Ephemeral execution/session IDs are not immutable scientific run IDs. Canonical scientific serialization is a separate shared Go output, without clocks/progress/UI timestamps; compare its original bytes across targets, never strip fields differently per runtime or compare rounded JS objects. Retain the original example-report gate unchanged.

Generate OpenAPI from authoritative Go DTO registrations and TypeScript bindings from that output, not hand-maintained parallel scientific types. Planner choice: Huma v2 with its stdlib-router adapter for incremental typed endpoint/schema registration on an internal module mux behind the existing server's security boundary; openapi-typescript plus openapi-fetch for generated TS bindings. Pin compatible versions in Go/npm locks during the owning implementation, record exact generator commands/digests and fail CI on regeneration drift. Keep Huma/native server dependencies out of WASM DTO/core packages. Disable automatic schema/docs/CDN routes and any automatic patch semantics; authentication/root/ETag policies remain explicit, not delegated to framework defaults. Retain RFC 9457 errors. This chooses the tools; exact compatible patch pins are routine implementation details, not a new architecture interview.
